**Rule‑based система для интерпретации лабораторных данных.** Анализирует результаты анализов и выдаёт структурированное заключение с рекомендациями, оценкой риска и детальными клиническими инсайтами (шпаргалкой для врача).

> **English:** A rule‑based laboratory data interpretation system that provides structured conclusions with recommendations, risk assessment, and detailed clinical insights (cheat sheet for clinicians).

## ✨ Ключевые возможности

| Категория | Описание |
|-----------|----------|
| **🧪 Интерпретация** | **243 клинических правила** (13 enriched + 230 basic), покрывающие основные синдромы и отклонения |
| **⚥ Пол** | Половозависимые референсные интервалы для 10+ параметров |
| **🔗 Комбинации** | Синдромы на основе нескольких находок (гиперпаратиреоз, септический синдром и др.) |
| **📋 Заключение** | Группировка по системам органов, дедупликация, описания |
| **🧠 Инсайты** | Критерии, дифференциальная диагностика, красные флаги, тактика, ссылки на гайдлайны (для enriched-правил) |
| **👨‍⚕️ Рекомендации** | Специальность, срочность, перечень дополнительных тестов |
| **📊 История** | SQLite с загрузкой последнего отчёта по ID пациента |
| **🔐 Безопасность** | JWT-аутентификация с ролями (`admin`, `doctor`, `user`) |
| **🖥️ UI** | Streamlit с автодополнением, цветовой индикацией риска, интерактивными карточками |
| **📄 PDF** | Экспорт заключения с поддержкой кириллицы |
| **🔄 Горячая загрузка** | Обновление правил без перезапуска контейнера |
| **🐳 Docker** | Запуск одной командой (`docker-compose up -d`) |

## 🆕 Что нового (последние улучшения)

- **Версионирование правил** – каждое изменение сохраняется с историей, возможен откат.
- **Кэширование результатов** (Redis) – ускоряет повторные запросы.
- **Аудит действий** – все запросы логируются в БД.
- **Физиологическая валидация** – проверка входных данных на абсолютные границы.
- **Разрешение конфликтов** – правила имеют приоритеты и списки конфликтующих.
- **Разделение правил на enriched и basic** – 13 проработанных сценариев с полными инсайтами, остальные – базовые пороги.

## 🏗️ Архитектура

Проект следует принципам **чистой архитектуры** (Clean Architecture / Ports & Adapters):
MedCDSS-RB/
├── domain/ # Ядро (сущности, value objects, бизнес-логика)
├── application/ # Сценарии и порты (интерфейсы)
├── infrastructure/ # Адаптеры (загрузчики, парсеры, хранилище, DI)
│ ├── repositories/ # SQLAlchemy-репозитории для правил и аудита
│ └── cache/ # Redis-кэш
├── api/ # REST API (FastAPI, аутентификация)
├── knowledge/ # Конфигурации в YAML (пороги, правила, интерпретации)
├── tests/ # Тесты (pytest, 43 теста проходят)
├── docs/ # Документация
├── streamlit_app.py # Веб-интерфейс
└── docker-compose.yml # Запуск API + UI одной командой

🩺 Клинические инсайты (советы для врача)
Для каждого enriched правила система предоставляет:

Критерии – какие параметры и пороги сработали.

Дифференциальную диагностику – возможные альтернативы.

Красные флаги – ситуации, требующие немедленного внимания.

Советы по тактике – пошаговые действия.

Ссылки на актуальные клинические рекомендации (KDIGO, ADA, ESC и др.).

На данный момент 13 правил имеют полный набор инсайтов, остальные 230 – базовые пороги. Планируется расширение числа обогащённых правил.
